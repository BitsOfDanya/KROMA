# Пилотная выборка для оценки качества

`research/experiments/build_evaluation_cohort.py` создаёт воспроизводимый набор кандидатов из [опубликованного NASA примера VIIRS S-NPP](https://firms.modaps.eosdis.nasa.gov/content/academy/data_ingest/firms_data_ingest.html). Файл от 12 июля 2023 года проверяется по SHA-256 перед обработкой. Команда из корня репозитория после установки `backend`:

```bash
python research/experiments/build_evaluation_cohort.py --download
```

Результаты находятся в исключённых из Git `data/raw/`, `data/interim/` и `data/samples/`. [Зафиксированный manifest](../../research/experiments/viirs-pilot-manifest.json) содержит ссылку, SHA-256 входа, число нормализованных записей, правило отбора и SHA-256 итогового JSONL. На исходном файле получено 74 599 уникальных наблюдений и 200 кандидатов из пяти доступных страт. Два последовательных запуска дали одинаковый SHA-256 итогового JSONL.

Пилот отбирает до 40 наблюдений в каждой паре `source_confidence` × `daynight` по детерминированному хешу ID. Разбиение `train`/`validation`/`test` назначается целым географическим ячейкам 5° × 5°. Это набор **кандидатов для независимой разметки**, а не готовые метки пожаров. `reference_label` остаётся `null`.

Для разметки нужно сохранить ссылку на подтверждающее свидетельство, дату проверки, тип объекта (`fire`, `non_fire`, `uncertain`) и проверяющего. Спутниковая confidence категория не может служить эталонной меткой. При неоднозначных случаях нужен второй проверяющий. После разметки можно считать precision, recall и ошибки отдельно по регионам, времени суток и confidence категориям. Для полноценного бенчмарка понадобятся несколько сезонов, независимые регионы и отрицательные примеры вне FIRMS; этот пилот не измеряет полноту обнаружения всех пожаров.
