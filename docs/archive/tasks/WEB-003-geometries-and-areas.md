# WEB-003. Геометрии зон и воспроизводимый расчёт площадей

Статус: DONE (19.09.2026). Приоритет: P0. Область: geo, backend. Критерии: R2, R3.

Зависимости: WEB-001; фикстуры/метаданные WEB-002. Реальные данные нужны для финальной приёмки.

## Цель и подтверждённая проблема

Зоны классов должны быть неперекрывающимися, а атрибут `area_ha` — соответствовать геометрии. Сейчас `backend/app/demo/dataset.py` создаёт вложенные заполненные полигоны. На момент аудита у `BS-2026-064` были следующие значения:

| Класс | Атрибут, га | Пересчёт геометрии существующей геоутилитой, га |
| --- | --- | --- |
| low | 122 | около 814 |
| moderate | 391 | около 660 |
| high | 301 | около 301 |

Новый экспорт не должен наследовать такую структуру. Полный контур и зоны нельзя складывать вместе.

## Что сделать

1. Реализовать в `geo/src/kroma_geo/` изолированные функции векторизации/валидации, перепроецирования, пересечения с AOI, измерения и проверки перекрытий.
2. Для результатов модели получать зоны из классов маски, сохранять отверстия, отдельные острова и nodata. Не создавать зоны искусственным масштабированием общего контура.
3. Поддержать Polygon/MultiPolygon в новых доменных/выходных схемах. Согласовать замкнутость колец и orientation выходного GeoJSON.
4. Применять правило выбора одной оценки на гарь до агрегирования. Перекрытия разных гарей/оценок не должны молча удваивать площадь: исправить происхождение/идентификацию либо отклонить противоречивый набор с диагностикой.
5. Обрезать зоны областью запроса. В bbox на краю гари учитывать только пересечение; касание точкой/линией не добавляет площадь и новую гарь.
6. Выбрать корректную CRS расчёта для подготовленного набора, сохранить её в metadata. Не измерять гектары в градусах или Web Mercator.
7. Считать площадь после обрезки. Сохранять достаточную точность, округлять только на границе вывода.
8. Рассчитать общую площадь, три класса, доли и количество уникальных гарей из одного набора зон.
9. Зафиксировать политику невалидной геометрии: допустимое исправление проверяется на изменение площади; существенная ошибка не исправляется молча. Записать предупреждение или отклонить набор.
10. Если старые demo-зоны доступны для скачивания/новой справки, исправить их топологию отдельным явным преобразованием и оставить происхождение `synthetic_demo`. Не смешивать это с векторизацией результатов модели.

## Результат

Чистые тестируемые geo-функции, адаптация схем, документация метода расчёта и набор эталонных геометрических тестов. Старые рендеринг-слои проверить после появления MultiPolygon.

## Критерии приёмки

- [ ] Геометрии валидны, находятся внутри выбранной области, имеют корректные кольца/отверстия.
- [ ] Классы не пересекаются по положительной площади; повторные оценки не увеличивают итог.
- [ ] `area_ha` относится именно к выдаваемой геометрии, не к исходной целой гари.
- [ ] Сумма площадей зон по классу совпадает со справкой; сумма трёх классов — с общей площадью.
- [ ] Площадь сопоставлена с исходной маской и геопривязкой; разрешение/nodata не игнорируются.
- [ ] Метод, CRS, правила обрезки, дедупликации и погрешность задокументированы.

## Проверки

- Метрическая маска 20 × 20 м: один валидный горелый пиксель — 0,04 га, половинное геометрическое пересечение — 0,02 га.
- Полигон с отверстием; две несвязанные части; bbox полностью внутри/снаружи/на границе; MultiPolygon.
- Повторная оценка той же гари, одинаковая зона дважды, пересекающиеся классы, самопересечение.
- Проверка после обратного преобразования в WGS84 и повторного чтения экспортного GeoJSON.
- Для сумм внутри одного расчёта использовать строгую машинную погрешность. Для независимого пересчёта геометрии ориентир допуска `max(0,01 га, 0,000001 × площадь)`; уточнить по выбранным проекциям/точности и обосновать, не маскировать этим систематические ошибки.

## Вне задачи

Улучшение точности сегментационной модели, обобщение контуров для красивого отображения с потерей точности, автоматическое исправление любой геометрии без проверки.
